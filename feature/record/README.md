# 기록 캘린더 상세 흐름

- 캘린더 셀과 다가오는 약속은 `CalendarEntry.id`를 상세 경로의 `entryId`로 전달한다. 시계는 확정 약속, 하트는 버킷, 사진은 완료 기록이다.
- 미션 제목·장소·추천 활동·준비물·주변 장소는 기존 `MissionRepository`의 `missionId`로 조회한다. 동일 미션의 약속 날짜와 사진 기록은 별도 발생 건으로 관리한다.
- 홈에 존재하는 동일 약속은 기존 `DetailRepository`를 통해 조회하고 컨디션을 적용한다. 기록 화면 전용으로 미션 내용을 복제하지 않는다.
- `RecordRepository.records`를 캘린더와 상세가 구독하므로 대표사진 변경은 두 화면에 함께 반영된다. 사진 선택·기록 편집·컨디션 선택의 초안은 상세 화면의 `SavedStateHandle`에 보존한다.
- 기록 수정과 삭제는 작성자 소유권을 저장소에서 검증한다. 대표사진은 해당 활동의 사진만 선택할 수 있다. 사진이 없던 기존 기록도 글을 수정할 수 있다.
- 상세·컨디션·편집 화면은 기록 탭의 이름 공간과 백스택을 유지한다. 사진 선택은 전체 화면 다이얼로그 경로이며 저장 후 원래 상세로 돌아가 상단 완료 메시지를 보여준다.

현재 `FakeRecordRepository`는 기존 홈·미션 데모 저장소에 연결된 **프로세스 내 임시 구현**이다. 가족 서버 동기화·사진 업로드·앱 재시작 후 영구 저장은 API 저장소로 교체해야 한다. `demo:group`과 `demo:pixel`은 제공된 Figma 사진을 화면 계층에서 로컬 리소스로 연결하는 데모 키다.

검증 범위: 공유 미션/약속 내용, 당일 컨디션 제한, 사진 소속 검증, 대표사진과 캘린더 동기화, 수정 초안 복원, 저장 실패 후 재시도, 수정/삭제 소유권, 시계·하트·사진의 실제 화면 이동.
